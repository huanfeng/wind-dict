# 码表反查读兄弟项目的数据，不自己分发

查一个字，顺带告诉用户它在五笔这类输入方案里**怎么打、怎么拆**。数据不随本程序分发，
从机器上已装的清风输入法（WindInput）那里探测。

## 为什么不随包带一份

拆字表（`wubi86_chaizi.txt`）与字根字体（`HeiTiZiGen.ttf`）在 WindInput 的 NOTICE.md 里
记的是「来源及作者不详，未附带任何版权声明」。兄弟项目以「权利人认为不当请联系」的方式
使用它，那是它的决定；本项目是**独立分发**的产品，多一个分发渠道就多一份暴露，而这份
数据我们并没有更清楚的授权依据。

探测已装的那份则没有这个问题：数据在用户自己机器上，本程序只是读它。

代价是没装 WindInput 的用户看不到这个功能。这是可以接受的——本项目是词典，码表反查是
**增益而不是前提**，探测不到时它整个不出现，不留下任何残缺的入口。

## 按方案自描述发现，不写死五笔

WindInput 的方案是自描述的：`<方案>.schema.toml` 里的 `[engine.chaizi]` 段自带拆字表
路径、字根字体路径与字体家族名。本项目照这个格式扫目录，于是：

- 不需要认识「五笔」这个具体方案——扫到什么就有什么；
- 虎码、小鹤这类第三方方案按同一格式放进去就自动出现，**不用改一行代码**。

写死五笔的话，每多支持一个方案就要改一次代码、发一次版，而用户完全有能力自己准备数据。

没有 `[engine.chaizi]` 的方案（拼音、双拼、英文）直接跳过：它们回答不了「这个字怎么拆」。

## 探测按「那里有没有东西」，不按名字

两处目录，缺一不可：

| 哪里 | 装什么 | 怎么找到 |
|---|---|---|
| 安装目录 `data\schemas` | 随程序分发的方案（五笔） | 注册表卸载项的 `InstallLocation` |
| 用户数据目录 `schemas` | 用户自己放的方案 | `%LOCALAPPDATA%\<产品>\datadir.conf` 里那一行 |

**卸载项按 `InstallLocation` 下有没有 `data\schemas` 判定，不按键名。** 那个键名是产品
显示名（开发机上是「清风输入法」与「清风输入法 (开发版)」），会随品牌、语言、版本变；
而「这个目录下有没有方案数据」是个客观事实。副产品是同时装了正式版与开发版时两个都能
找到，各自成为一处来源。

**用户数据目录必须去问 `datadir.conf`，不能猜。** 开发机上它就被搬到了
`D:\UserData\输入法数据\WindInput`——「安装目录下的某个子目录」这条路一开始就是错的。

同一个方案 id 只取第一处：两个版本都有 `wubi86`，出现两个同名页签只会让人以为看重影了。

探测覆盖不到的情形（便携版、解压即用、装在别处）由设置页手动指定目录兜底。

## 只做「由字查码」

反查在输入法语境里就是这个方向。反过来「由码查字」要另建一套倒排索引，且与英文查询天然
打架——`stand` 既是英文词也是一串合法五笔码，界面无从判断用户要哪个。真要做，那是一个
需要单独设计入口的功能，不是这一个的附赠。

## 逐字列出，不编造词的编码

拆字表讲的是**单字**怎么拆。词的编码由各方案的造词规则算出来（`[encoder.rules]`），不在
这份数据里，本项目**不去实现那套规则**：算错一个编码比不给编码更糟——用户会照着它去打，
然后发现打不出来。

而逐字列出恰好是有用的那一面：查「输入法」得到三行「输 lwgj / 入 tyi / 法 ifcy」，那正是
想不起某个字怎么打时要看的东西。

## 字根是私用区字符

五笔的字根落在 Unicode 私用区，非得配字根字体才显示得出来，否则是一排方框。装了 WindInput
的机器上那个字体已经在系统字体库里（它的安装器会装），故按 `font_family` 直接用。

windui 另有 `text::register_private_use_font` 可以从文件加载而不必装进系统，但它是**全局
单例**（重复调用以最后一次为准），多个带私用区字根的方案不能同时显示。目前没有走这条路：
用汉字部件当字根的方案（虎码等）没有这个问题，而五笔那份靠系统字体已经够了。真遇到两个
都要私用区字体的方案，那时再设计如何取舍。

## 码表排在释义之后

查词的人多数时候要的是「这个词什么意思」，码表回答的是「这个词怎么打」。把编码顶到释义
前面等于替用户改了目的。页签里同理，它排在所有词典之后。

## 与自带词典共用的几处

- **改名**走 `Settings::dict_names`，键是方案 id。
- **开关**走 `Settings::disabled_dicts`，与自带词典共用一张表（方案 id 与 `.mdx` 文件名
  不会撞）。
- **页签**是 `TabKey::Code(方案 id)`，与 ADR-0018 定的「按来源分页签」一致。

设置页分两组列而不是合成一组：自带词典是用户丢进词典目录的文件，码表是从兄弟项目探测来的
方案，两者的来源、目录、失败方式都不同。
