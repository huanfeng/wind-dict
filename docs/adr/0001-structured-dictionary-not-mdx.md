# 离线词典采用结构化词库（ECDICT），不支持 MDX / StarDict

本项目的 UI 框架 windui 没有任何富文本渲染能力：`Element::label` 只接受纯字符串，样式挂在 Element 而非文本片段上，混排需用多个 Element 拼接。而词典界主流格式 MDX（мdict）与 StarDict 的正文是 HTML + CSS——支持它们意味着必须在 windui 上从零实现一个 HTML 子集渲染器（解析、盒模型、内联排版、CSS 子集），工作量超过词典工具本体。因此我们选择字段化的结构化词库 ECDICT（MIT，约 77 万英汉词条），其每个字段均为纯文本，可直接映射到 windui 现成控件。

## 被拒绝的方案

**MDX 格式（欧路 / GoldenDict 生态）**：词库生态巨大、内容质量高（牛津高阶等），用户可用户词典。拒绝原因不是格式本身难解（虽然它确实是逆向工程产物、含 LZO/zlib 多版本压缩），而是**正文的 HTML 与 windui 的能力根本不兼容**。这个否决对未来同样成立——除非 windui 获得富文本渲染能力，否则重新考虑 MDX 都是错的。

> **后续变更（ADR-0015）**：上面那个否决条件已经满足，MDX 用户词典已经支持。但满足的是「富文本渲染」，**不是**「HTML+CSS 渲染器」——本 ADR 关于后者的判断原样成立，建成的是一个有界的标签映射器，层级信息仍会丢。下面「用户无法用户词典」那条后果因此作废，其余各条不变。

**StarDict**：同上，正文多为 HTML 或 Pango 标记。

## 后果

- 离线查询**仅限英汉**。中日韩等其他语种、以及例句/词源等 ECDICT 不含的内容，离线不可得，只能走在线查询。
- 离线释义相对简略，无例句。这是已知且接受的代价。
- ~~用户**无法用户词典**。这是一个明确的「不做」——它换来的是零 HTML 渲染代码。~~
  （已被 ADR-0015 推翻：可自带 MDX，代价是一个有界的标签映射器，仍无 CSS。）
- ECDICT 的 `exchange` 字段自带词形变化数据，因此本项目**不需要词干提取算法**（Porter/Snowball 等）。这是选择该词库的额外收益，也是一个不应被「优化」掉的依赖。
