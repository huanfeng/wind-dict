# ESC 隐藏窗口，失焦不隐藏

主窗口是一个普通窗口：ESC 或点击关闭按钮 → 隐藏到托盘（不退出进程）；失去焦点 → **保持可见**。

## 为什么不做失焦即隐藏

热键唤起类工具（Alfred、PowerToys Run）以失焦即隐为标准行为，因此这个偏离需要解释。区别在于产出物的性质：启动器的产出是一个**动作**，动作执行完窗口即无用；词典的产出是**信息**，而信息需要被阅读、抄写、对照。

失焦即隐会直接消灭两个真实场景：一边看释义一边在别处打字；以及选中释义文本复制走（后者甚至可能在拖选过程中误触隐藏）。有道词典本身也正是这样分裂处理的——主窗口是普通窗口，只有划词弹出的浮窗才失焦即隐。本项目 MVP 不含划词，因此当前只存在「主窗口」这一形态。

若未来加入划词浮窗，本决定**不适用于该浮窗**：浮窗的产出是一瞥即走的提示，失焦即隐对它是正确的。届时两种窗口形态并存，各有各的消失策略。

## 后果

- **windui 的失焦事件不再阻塞 MVP**（见 ADR-0004 缺口表）。该能力仅在未来实现划词浮窗时才需要。
- 用户可能忘记词典还开着。可接受：它是个普通窗口，行为与其他窗口一致，不会造成意外。
- ESC 的实现依赖 windui 的关闭拦截路径（`app.rs:1987`：ESC → `close_handler` → 返回 false 则不关闭）。但当前该回调不带 ctx，**无法在拦截的同时隐藏窗口**——这正是 ADR-0004 中必须补齐的缺口之一。

## 2026-09 订正：「隐藏」现在是「销毁」

窗口形态改成零窗口常驻之后（ADR-0006 第二次修订），ESC 与关闭按钮落成的是**关掉窗口**
而非隐藏它——进程照常留在托盘里等热键。

**本决定的实质未变**：用户按 ESC 想要的是「让它从眼前消失，但别退出」，这一条两种实现都
兑现了。变的是代价那一侧：此前隐藏留着一份看不见却照付的后备缓冲，现在那份随窗口一起
还回去。

查询词、历史、展开态活在窗口之外，再唤起时原样还在；**但窗口自身的状态不是**——尺寸与
位置不再保留（改为每次居中）、滚动位置与焦点归零。对「收起再唤起去查下一个词」这条主路
没有影响，而对「读长释义读到一半收起、回来接着读」是实打实的退步。这一条要如实记着，
别写成「用户感知不到区别」。

「失焦不隐藏」这一半完全不受影响，理由（词典的产出是**信息**，要被阅读、抄写、对照）与
窗口怎么消失无关。

文末那条「ESC 的实现依赖关闭拦截路径、而该回调不带 ctx」已过时：`on_close_request` 早已
带上 ctx，且本项目现在根本不需要拦截——关掉就是想要的结果，不必再转成隐藏。
