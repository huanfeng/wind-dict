# 随程序分发的词库按一个目录配置，且这个设置不得把自己锁死

`Settings` 用**一个** `dict_dir` 指向三份库（`ecdict.db` / `cedict.db` / `unihan.db`）
所在的目录，取代原先的两条文件路径加一条隐式约定。设置里的目录不可用时，程序**回退
到 exe 同目录**并在设置页如实标出，而不是启动失败。

## 三份库，一个目录

改之前是这样：

| 库 | 设置项 | 默认位置 |
|---|---|---|
| `ecdict.db` | 一个文件选择器 | exe 同目录 |
| `cedict.db` | 另一个文件选择器 | exe 同目录 |
| `unihan.db` | **没有** | 英汉库旁边，否则 exe 同目录 |

三份库永远住在一起、随同一次部署整体替换，却被拆成两个独立的选择器加一条看不见的
约定。两处代价：

- 两条路径**允许一种从不发生、却处处要防的状态**：英汉指向新版、汉英还指着旧版。
  没有任何用户想要它，而每一处读词库的代码都得假设它可能出现。
- 字形库的定位规则是隐式的，且与另外两份不同。同一件事两套规则，其中一套还看不见。

原先给字形库不设选项的理由写在代码里：「另外两份词库可以换（用户可能想塞一份更大的
ECDICT），字形库没有第二个版本可换」。这个理由**只支持「不必单独选字形库」**，不支持
「字形库该有一套自己的定位规则」——收进同一个目录之后，它跟着走，什么都不必多做。

## 这个设置曾经能把自己锁死

设置存的是路径，而路径会失效：换盘、挪目录、清理下载文件夹。原先的流程是：

1. 保存时校验通过 → 写进设置
2. 那个文件此后被移走
3. 下次启动 `main` 打不开词库 → 弹致命框 → **退出**
4. 而修改设置的入口在程序里面

用户进不去，也就改不回来，只剩手改 `%LOCALAPPDATA%` 里的 SQLite 一条路。**一个能把
自己锁死的设置项不该存在**，这与「保存前校验」是两件事——校验管的是当时，锁死发生在
之后。

现在：设置的目录不可用就回退 exe 同目录，程序照常启动，设置页把这件事写出来
（「设置的目录当前不可用，正在用：…」）并保留「恢复默认」。回退**不改设置**——
悄悄把用户填的值抹掉，比锁死好不了多少。

## 缺哪一份就报哪一份

词库确实缺失时仍然是致命的（ADR-0001 与 `OfflineDictionary::open` 的理由不变：与其
起一个查什么都「未收录」的空壳去撒谎，不如失败）。改的是**说法**：此前只讲「无法打开
词库」再附一段 anyhow 的因果链，用户看到一屏读不懂的东西，而他需要知道的只有「哪个
文件不在」。

判据顺带也变严了：`check_dir` 会**真开一次并试查**，不只看文件在不在。把汉英库改名成
`ecdict.db` 放进去，只看名字的检查会照收，而两个库的表结构完全不同。

## 设置页报文件大小，不报词条数

「英汉 162 MB · 汉英 15 MB · 字形 4 MB」而不是「英汉 77 万 · 汉英 12 万」。

`SELECT count(*)` 在这三个库上实测各要 170–210 ms，而设置页每次换肤、每次拨开关都要
重建——三份加起来半秒的卡顿，换来的是用户分辨不出的信息（770,611 与 700,000 看着
一样），而 162 MB 与 0 字节一眼就能分辨。这一行要回答的问题是「这个目录里的库在不在、
是不是完整那份」，大小回答得了。

## 与自带词典的词典目录不是同一件事

两者形状相同（一个目录），但性质不同，别把它们的规则互相搬运：

| | 词库目录（本 ADR） | 词典目录（ADR-0015） |
|---|---|---|
| 归属 | 产品的一部分，随部署替换 | 用户自己的文件 |
| 数量 | 恰好三份，文件名固定 | 任意多本，名字随意 |
| 缺失 | 致命（两份必需的） | 正常（还没放东西） |
| 默认位置 | exe 同目录 | 用户数据目录下的 `dicts` |
| 扫描 | 不扫，按固定文件名取 | 递归三层 |
| 开关 | 无（不存在「关掉英汉库」） | 每本一个 |

「默认位置」那一行尤其不能互换：词库跟着部署走，卸载连同删掉正是对的；词典是用户
下载的，卸载删掉它是事故（ADR-0011）。

## 后果

- `Settings` 的 `ecdict` / `cedict` 两项合成 `dict_dir`。旧值有迁移：取英汉库所在的
  目录——三份库本就同处一处，故这个推断在旧数据上必然成立。不迁移的话，设置过词库
  路径的用户升级后会被静默拽回程序同目录：查得到词、一切正常，只是用的不是他指定的
  那份库，而这种「没坏但不对」最难被发现。
- 命令行的位置参数从「两个文件」变成「一个目录」：`wind-dict .cache\dict`。
- `exe_dir()` 从 `main.rs` 搬进 `source::offline`——设置页也要用它算「此刻在用哪个
  目录」，而这件事写两遍就等着漂移。
- `probe_dict(path, is_ec)` 换成 `check_dir(dir)`，返回三份库各自的状况而非一个布尔。
